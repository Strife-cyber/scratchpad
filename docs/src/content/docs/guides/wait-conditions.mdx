## Auto-Wait (Playwright-Style)

When using selector-based actions (click, type, hover, double_click, right_click, drag_drop), the engine automatically waits for the target element before performing the interaction. This means explicit `wait` calls are often unnecessary when you provide a selector.

### How It Works

1. The engine polls the DOM at **50ms intervals** for an element matching the selector that is both **visible** and **enabled**.
2. If no matching element is found within the timeout (default **10 seconds**, configurable via `timeout_ms`), an error is returned.
3. If the element is found but is not visible, the error includes the hint `"try scroll_into_view"`.
4. After a successful action, the engine briefly waits for page stability (network idle + 100ms quiet period) before returning.

### Affected Actions

All of the following actions auto-wait when a `selector` is provided:

- `click`
- `type`
- `hover`
- `double_click`
- `right_click`
- `drag_drop`

### Example

```json
{
  "action": "click",
  "selector": {"css": "#submit-btn"}
}
```

The engine waits for `#submit-btn` to be visible and enabled, clicks it, then waits for page stability.

### Comparison Table

| Behavior | Old (manual wait) | New (auto-wait) |
|----------|-------------------|-----------------|
| Polling interval | ~100ms | **50ms** |
| Default timeout | 10000ms | 10000ms |
| Post-action stability | None | Network idle + 100ms quiet |
| Element visibility check | In `wait` action only | Built into every action |
| Error messaging | Generic | Selector + match count + hint |

---

The `wait` action pauses execution until a condition is met or a timeout expires.

## Basic Usage

```json
{"action": "wait", "condition": "network_idle", "timeout_ms": 10000}
```

## Wait Conditions

### network_idle (Chrome only)

Waits until no network requests are in-flight. Useful after navigation or before interacting with dynamically loaded content:

```json
{"action": "wait", "condition": "network_idle"}
```

### selector_visible

Waits for an element matching the selector to become visible on screen:

```json
{
  "action": "wait",
  "condition": "selector_visible",
  "selector": {"css": ".content-loaded"}
}
```

### selector_hidden

Waits for an element to disappear or become hidden:

```json
{
  "action": "wait",
  "condition": "selector_hidden",
  "selector": {"css": ".loading-spinner"}
}
```

### selector_enabled

Waits for a disabled element to become enabled:

```json
{
  "action": "wait",
  "condition": "selector_enabled",
  "selector": {"css": "#submit-btn"}
}
```

### text_appear

Waits for specific text to appear on the page, optionally scoped to a selector:

```json
{
  "action": "wait",
  "condition": "text_appear",
  "selector": {"css": ".status-message"},
  "text": "Success"
}
```

### url_match

Waits for the current URL to match a pattern (useful for SPA routing):

```json
{
  "action": "wait",
  "condition": "url_match",
  "pattern": "/dashboard"
}
```

### Timeout Fallback

If no condition is specified, wait acts as a simple sleep:

```json
{"action": "wait", "timeout_ms": 5000}
```

## Defaults

| Field | Default | Description |
|-------|---------|-------------|
| `timeout_ms` | 10000 | Maximum wait time in milliseconds |
| `condition` | `""` | Wait condition type |
| Polling interval | 50ms | How often conditions are re-checked |
