title: Selectors

Selectors let you target elements on the page without needing to know their exact coordinates. The engine resolves selectors using a specificity hierarchy.

## Selector Specificity

Selectors are evaluated in order of specificity. The first matching strategy wins:

1. **CSS** — highest specificity
2. **XPath**
3. **Text** — element text content
4. **Role** — ARIA role
5. **TestID** — `data-testid` / `data-test-id`
6. **Placeholder** — lowest specificity

## Selector Types

### CSS Selector

Uses `document.querySelectorAll()`. Supports standard CSS selectors:

```json
{"selector": {"css": "#submit-btn"}}
{"selector": {"css": ".nav-item.active"}}
{"selector": {"css": "form input[type='email']"}}
{"selector": {"css": "button:contains('Login')"}}
```

### XPath Selector

Uses `document.evaluate()` for flexible DOM traversal:

```json
{"selector": {"xpath": "//button[contains(text(),'Submit')]"}
{"selector": {"xpath": "//div[@class='content']//a[2]"}
```

### Text Selector

Matches elements containing the given text:

```json
{"selector": {"text": "Sign In"}}
{"selector": {"text": "Welcome back, John"}}
```

### Role Selector

Matches elements by ARIA role or aria-label attribute:

```json
{"selector": {"role": "button"}}
{"selector": {"role": "dialog"}}
{"selector": {"role": "search"}}
```

### TestID Selector

Matches elements with `data-testid` or `data-test-id` attributes:

```json
{"selector": {"testid": "checkout-button"}}
```

### Placeholder Selector

Matches input elements by their `placeholder` attribute:

```json
{"selector": {"placeholder": "Enter your email"}}
```

## Combining Selectors

You can include multiple fields in a single selector. The engine tries each in specificity order until one matches:

```json
{
  "selector": {
    "css": "#login-form",
    "text": "Sign In",
    "role": "button"
  }
}
```

## Android Selector Translation

On Android, CSS-like selectors are translated to UIAutomator node property matching:

| Selector | Android Behavior |
|----------|-----------------|
| `css` starts with `#` | Matches node **name** by substring |
| `css` starts with `.` | Matches node **class/role** by substring |
| `css` plain text | Matches node **name** by substring |
| `text` | Case-insensitive name substring match |
| `role` | Case-insensitive class substring match |
| `testid` | Content-desc substring match |
| `placeholder` | Content-desc substring match |

## Element Highlighting

When an action targets an element using a **CSS selector**, the engine highlights the element before interacting with it:

- A **red outline** is applied to the matched element.
- A screenshot of the highlighted element is captured and included in the response as `ActionResult.element_highlight`.

This visual feedback makes it easy to verify that the engine is targeting the correct element, especially during debugging.

| Action | Highlighting Behavior |
|--------|-----------------------|
| `click` | Red outline applied before click |
| `type` | Red outline applied before focusing |
| `hover` | Red outline applied before hover |

```json
{
  "action": "click",
  "selector": {"css": "#submit-btn"}
}
// Response includes: element_highlight: "<base64_png_screenshot>"
```

## Playwright-Style Auto-Wait

Selector-based actions (`click`, `type`, `hover`, `double_click`, `right_click`, `drag_drop`) now include built-in auto-wait behavior:

- The engine polls at **50ms intervals** for a visible and enabled element matching the selector.
- Default timeout is **10 seconds** (configurable via `timeout_ms`).
- If the element is not visible, the error includes `"try scroll_into_view"`.
- After the action, the engine waits for **network idle + 100ms quiet period**.

### Rich Error Messages

When an action fails, the error response includes detailed diagnostics:

| Field | Description |
|-------|-------------|
| `selector` | The selector string that was tried (e.g. `"css=#submit-btn"`) |
| `matches` | How many elements matched the selector |
| `visible` | How many matched elements were visible |
| `enabled` | How many matched elements were enabled |
| `hint` | A descriptive hint about the failure |

```json
{
  "error": "Element not available",
  "details": {
    "selector": "css=#submit-btn",
    "matches": 1,
    "visible": 0,
    "enabled": 0,
    "hint": "Element is not visible — try scroll_into_view"
  }
}
```

### Selector Object Methods

The `Selector` object has been extended with two new utility methods:

- **`Describe()`** — returns a human-readable string like `"css=#submit-btn"` or `"text=Sign In"`.
- **`IsEmpty()`** — returns `true` if the selector has no fields set.

This means you no longer need to explicitly call `wait` before actions that use selectors — the engine handles it for you.
