## Server Configuration

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `CHROME_PATH` | auto-detect | Path to Chrome/Chromium executable |
| `SCRATCHPAD_HEADLESS` | `true` | Run browser in headless mode. Set to `false` to see the browser window |
| `SCRATCHPAD_VIDEO_DIR` | `./videos` | Directory for screen recording output files |
| `SCRATCHPAD_TRACE_DIR` | `./traces` | Directory for CDP performance trace files |

### Address and Port

The server listens on `127.0.0.1:8080` by default.

| Flag | Environment variable | Description |
|------|----------------------|-------------|
| `--port` | `SCRATCHPAD_PORT` | Listen port (default `8080`) |
| `--bind` | `SCRATCHPAD_BIND` | Listen address: `host:port`, or a host alone (`0.0.0.0`, `::1`) combined with the port |

Flags win over environment variables. If `--bind` already contains a port, a
different `--port`/`SCRATCHPAD_PORT` is an error rather than being silently
ignored. Binding anything other than loopback requires `--token` or
`--allow-shared-sessions`.

```bash
scratchpad --port 9000                       # 127.0.0.1:9000
SCRATCHPAD_PORT=9000 scratchpad              # same
scratchpad --bind 0.0.0.0 --port 9000 --token "$SCRATCHPAD_TOKEN"
```

`SCRATCHPAD_PORT` is also read by the clients: the CLI (`run`, `doctor`,
`timeline`, …) and the MCP bridge default to `localhost:$SCRATCHPAD_PORT`, so
setting it once keeps the server and its clients in agreement. Their
`--server`/`--engine-url` flags (and `SCRATCHPAD_URL` for the bridge) still
override it.

### Platform Selection

The server listens on two WebSocket endpoints:
- `ws://localhost:8080/ws` — Chrome/Chromium browser automation
- `ws://localhost:8080/ws/android` — Android device automation

Create sessions via the HTTP API with the desired platform:
```bash
# Web browser session
curl -X POST http://localhost:8080/api/v1/sessions \
  -H "Content-Type: application/json" \
  -d '{"platform":"web","headless":true}'

# Android session
curl -X POST http://localhost:8080/api/v1/sessions \
  -H "Content-Type: application/json" \
  -d '{"platform":"android"}'
```

The `-kind` field (`"chrome"` or `"android"`) is an alias for `-platform`.

## CLI Test Runner

The `scratchpad-cli run` command accepts these flags:

```bash
scratchpad-cli run -i <suite.yml> [flags]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-i` | (required) | Path to YAML or JSON test suite file |
| `-server` | `http://localhost:$SCRATCHPAD_PORT` (8080) | Scratchpad server URL |
| `-headless` | `true` | Run browser headless |
| `-platform` | `"web"` | Target platform: `"web"` or `"android"` |
| `-parallel` | `1` | Maximum parallel suite execution |
| `-retries` | `0` | Number of retries on suite failure |
| `-timeout-ms` | `60000` | HTTP timeout per suite in milliseconds |
| `-format` | `"json"` | Report format: `"json"`, `"junit"`, or `"both"` |
| `-out` | `""` | JSON report output file path |
| `-junit-out` | `""` | JUnit XML output file path |

## MCP Bridge

The MCP bridge connects AI agents to Scratchpad via the Model Context Protocol:

```bash
scratchpad-cli mcp [flags]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--engine-url` | `$SCRATCHPAD_URL`, else `ws://localhost:$SCRATCHPAD_PORT/ws` (8080) | WebSocket engine URL |
| `--name` | `"Browser-Engine-MCP"` | MCP server name |
| `--version` | `"1.0.0"` | MCP server version |
