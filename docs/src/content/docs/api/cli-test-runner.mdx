The CLI test runner executes test suites defined in YAML or JSON files.

## Commands

### Run Tests

```bash
scratchpad-cli run -i <suite-file> [flags]
```

### MCP Bridge

```bash
scratchpad-cli mcp [flags]
```

## Suite File Format

Suites can be defined in three formats:

**Multiple named suites:**

```yaml
- name: "Login Test"
  platform: "web"
  steps:
    - navigate: "https://example.com/login"
    - type: {selector: {css: "#username"}, text: "user"}
    - click: {selector: {css: "#login-btn"}}

- name: "Dashboard Test"
  steps:
    - navigate: "https://example.com/dashboard"
    - assert: {selector: {css: ".stats"}, text: "Welcome", contains: true}
```

**Single unnamed suite (flat steps list):**

```yaml
- navigate: "https://example.com"
- observe: {}
- click: {selector: {css: "a"}}
```

**Single suite object:**

```yaml
name: "Checkout Flow"
platform: "web"
steps:
  - navigate: "https://shop.example.com"
  - click: {selector: {text: "Add to Cart"}}
```

### Selectors

A selector is either a CSS string shorthand or a structured mapping with one or
more strategies. Resolution order: `css` > `xpath` > `text` > `role`+`name` >
`role` > `name` > `test_id` > `placeholder`.

```yaml
- click: {selector: {css: "#save-btn"}}
- click: {selector: {xpath: "//button[@id='save']"}}
- click: {selector: {text: "Save"}}
- click: {selector: {test_id: "save-btn"}}
- click: {selector: {role: button, name: "Save"}}   # Strongest locator
- assert: {selector: {role: link, name: "Home"}, visible: true}
```

`role` matches the computed role — an explicit `role`/`aria-role` attribute or
the element's implicit role (`button`, `link` for `<a href>`, `combobox`,
`textbox`, `heading`, `checkbox`, `radio`, `image`, …). `name` is the accessible
name: `aria-label`, `aria-labelledby`, `title`, or visible text. Together,
`role` + `name` locates an element exactly the way the engine's observation tree
describes it.

## Step Types

### navigate

```yaml
- navigate: "https://example.com"
```

### wait

```yaml
- wait: {selector: {css: ".loaded"}, timeout: 5000}
- wait: {condition: "network_idle"}
- wait: {condition: "text_appear", selector: {css: ".msg"}, text: "Done"}
```

### type

```yaml
- type: {selector: {css: "#username"}, text: "myuser"}
```

### click

```yaml
- click: {selector: {css: "#btn"}}           # Object form
- click: "#btn"                                 # String shorthand (CSS)
```

### assert

```yaml
- assert: {selector: {css: "h1"}, text: "Dashboard"}
- assert: {selector: {css: ".error"}, text: "invalid", contains: true}
- assert: {selector: {css: ".price"}, text: "\\$[0-9]+", matches: true}
- assert: {selector: {css: "#loading"}, visible: true}
- assert: {selector: {css: ".item"}, exists: true}
- assert: {selector: {css: "#checkbox"}, checked: true}
- assert: {state: {document_status: "complete"}}
- assert: {state: {inflight_requests: 0}}
```

Assertion boolean fields map to types:

| Field | Assertion Type |
|-------|---------------|
| `equals` (default) | `text_equals` |
| `contains` | `text_contains` |
| `matches` | `text_matches` |
| `visible` | `element_visible` |
| `exists` | `element_exists` |
| `checked` | `element_checked` |

State assertions check page-level system state (no selector needed). Exactly one of
`document_status` or `inflight_requests` must be present:

- `state.document_status` — expected `document.readyState`: `loading`, `interactive`, or `complete`.
- `state.inflight_requests` — expected number of in-flight network requests (non-negative integer).

### observe

```yaml
- observe: {}
```

## Report Output

### JSON Report

```json
{
  "started_at": "2025-01-01T00:00:00Z",
  "duration_ms": 4520,
  "suites": [
    {
      "name": "Login Test",
      "passed": true,
      "attempts": 1,
      "duration_ms": 2100,
      "failure_step": null,
      "error": ""
    }
  ]
}
```

Compatible with standard CI/CD tools that consume JUnit reports.
